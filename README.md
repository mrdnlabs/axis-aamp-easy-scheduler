# AampEasyScheduler (ChAAMP)

> The codename for the user-facing product is **ChAAMP** — *Chat with AXIS Audio Manager Pro*. The repository name `AampEasyScheduler` is the original project name and remains in places where it's part of the package / module identity (`aamp-easy-scheduler`, `aamp.*` Python modules, `aamp-*` CLI commands). New surfaces ship under the ChAAMP name.

A natural-language scheduler for [AXIS Audio Manager Pro](https://www.axis.com/products/axis-audio-manager-pro). Lets administrators describe bell schedules (or any scheduled audio) in plain English and have them applied directly to AAM Pro — typically over a chat interface like Claude Code, the upcoming ChAAMP web app, or any MCP-compatible client. Also handles end-to-end onboarding of Axis network audio devices: discover them on the LAN, install the AAM Pro ACAP, point them at the server.

> Primary use case: K-12 school bell schedules. Also works for offices, retail, hospitals, transportation hubs, and other PA-system deployments.

## Requirements

- **Windows** (the project assumes AAM Pro is installed at its default Windows location and uses Windows-only PowerShell helpers for some optional tooling). Linux/Mac support would need path tweaks.
- **AXIS Audio Manager Pro** installed locally (bundles PostgreSQL on `localhost:5433`, the REST API on port 443, and the IAM on port 10032).
- **Python 3.12+**
- **An AAM Pro admin account** — create one in the SPA at *Settings → Users*.
- **Optional**: an [ElevenLabs](https://elevenlabs.io) API key for voice generation, and a Gemini API key if you want to use the bundled chat client (alternative: use Claude Code as your MCP client and skip the Gemini chat).

## Quickstart

```powershell
# 1. Clone and enter the directory
git clone https://github.com/mrdnlabs/axis-aamp-easy-scheduler.git
cd axis-aamp-easy-scheduler

# 2. Create a venv and install
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -e .

# 3. Configure credentials
copy .aamp_credentials.example .aamp_credentials
notepad .aamp_credentials     # fill in your AAM Pro user/password etc.

# 4. (Optional) Download seed audio assets — bells, effects, sample music
.\tools\download_seed_assets.ps1

# 5. Smoke-test the connection
python -c "from aamp.config import load_config; print(load_config())"
```

## Running the MCP server

The MCP server exposes 38+ tools for AAM Pro scheduling and Axis device management. Wire it into any MCP-compatible client:

```powershell
# Run as a standalone MCP server (stdio transport)
aamp-mcp
```

### Hooking up Claude Code

In `~/.claude/settings.json` (or `.claude/settings.json` per project):

```json
{
  "mcpServers": {
    "aamp": {
      "command": "C:\\path\\to\\axis-aamp-easy-scheduler\\.venv\\Scripts\\python.exe",
      "args": ["-m", "aamp.mcp_server"]
    }
  }
}
```

Then Claude Code (or any MCP client — including the bundled `aamp-chat` if you have a Gemini API key) sees all tools: `describe_site`, `create_template`, `schedule_template`, `discover_axis_devices`, `onboard_axis_device`, etc.

## Running the bundled chat client (optional)

```powershell
aamp-chat
```

Requires a `GEMINI_API_KEY` environment variable. The chat reads `src/aamp/system_prompt.md` for its bell-schedule-savvy persona and uses the MCP tools internally.

## Key capabilities

### AAM Pro scheduling

- Full CRUD over destinations, templates, schedulers, events, and music
- OAuth2/PKCE auth against the AAM Pro IAM
- PostgreSQL read-side for schema introspection
- Voice generation via ElevenLabs → upload → schedule pipeline
- File attachment support (PDF/CSV/image) for importing schedules

### Axis device onboarding

- **Discovery**: parallel mDNS (multi-service + meta-service browse), HTTP subnet sweep (with MAC harvest from the `AXIS_<MAC>` Digest realm), and ARP filter against the 4 IEEE-verified Axis OUIs. Optional SSDP and WS-Discovery for legacy firmware.
- **Classification**: distinguishes Axis audio endpoints (speakers, amplifiers, bridges, paging consoles) from AAM Pro server hardware vs. non-audio Axis products (cameras, intercoms, accessories). See `src/aamp/axis_models.py`.
- **Authentication**: tries fleet candidate passwords; auto-detects factory-default devices via `systemready.cgi?needsetup` and provisions root.
- **ACAP install**: model→arch resolution preferring the device-reported architecture from `basicdeviceinfo.cgi`.
- **Server pointer**: `param.cgi` write of `root.AudioManagerPro.PrimaryServerIpAddress`, with per-device interface inference for multi-homed AAM Pro servers.
- **Verified end-to-end** against a C1110-E on AXIS OS 12.9 — see `docs/axis_device_onboarding.md` for the empirical findings.

## Status

Functional but pre-1.0. Verified on:
- AAM Pro 5.1.34 server
- C1110-E speaker on AXIS OS 12.9.57

Other models / firmware versions may surface edge cases. The `MODEL_ARCH_TABLE` in `src/aamp/acap.py` is a heuristic fallback — the device's own `basicdeviceinfo.cgi` Architecture field is authoritative and is preferred whenever available.
